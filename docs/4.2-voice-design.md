# AIRI v4.2 — Voice input

Design doc. Source of truth for the v4.2 build. Agreed with the operator
2026-05-17. Companion to `docs/4.0-airi-design.md` (the AIRI design) and
`docs/4.1-capability-routing` work.

## 1. What v4.2 is

The AIRI chat panel gains **voice input**: an operator speaks a request
instead of typing it — at a desk or from a phone (the mobile app-shell has
been clean since v4.0.1). The assistant is "Airy"; the wake word is "Airy"
(decision #6 of the AIRI design).

v4.2.0 ships **push-to-talk**: the operator taps a mic button, speaks, and
the speech is transcribed into the chat input for review before sending.
The always-listening "Airy" wake word is designed here but lands in a
later hands-free milestone (§8). v4.2 is **input only** — AIRI does not
speak its answers back (that is a separate later capability).

## 2. Keystone constraint — audio stays on our infrastructure

Operator-locked rule (`feedback_open_source_only.md`): we own the
dependency chain; no paid SaaS, no third-party dependency for a new
component. The browser's built-in Web Speech API is therefore **ruled
out** — Chrome streams the microphone audio to Google's servers, which
would send operator-conversation audio off our infrastructure.

Speech-to-text is done with **self-hosted open-source Whisper**
(`faster-whisper` — CTranslate2, runs on CPU). The audio is captured in
the browser, posted to the proxy, transcribed on our own hardware, and
**immediately discarded**. It is never written to disk or the database.
Only the resulting *text* enters the conversation — and that text is
subject to the same PII masking and prompt-guard the typed path already
applies.

## 3. Architecture

```
browser mic ──MediaRecorder──> POST /api/airi/transcribe ──> whisper-bridge
 (webm/opus)                    (llm-proxy2, auth-gated)      (faster-whisper)
                                        │                          │
                                        └────── {text} ◄───────────┘
                          fills the AIRI chat input (operator reviews → Send)
```

- **`whisper-bridge`** — a small sidecar container (FastAPI + `faster-whisper`
  + ffmpeg), one per node, on the docker network only. Same pattern as the
  existing `grok-bridge` sidecar (`build:` a repo subdir, its own Dockerfile,
  not exposed through nginx). It exposes one route, `POST /transcribe`,
  guarded by a shared-secret bearer token.
- **`POST /api/airi/transcribe`** — a new llm-proxy2 endpoint. Admin-gated,
  `airi_enabled` + `airi_voice_enabled` gated. Accepts a multipart audio
  blob, forwards it to the sidecar, returns `{ "text": ... }`. The audio is
  streamed through, never persisted.
- **`AiriChatPanel`** — a mic button beside the text input. Tap to record,
  tap to stop; the transcript fills the input for the operator to review and
  edit, then Send (the existing chat path takes over unchanged).

## 4. The whisper-bridge sidecar

- **Stack:** FastAPI, `faster-whisper`, `ffmpeg` (for the browser's
  webm/opus and Safari's mp4 containers). Lives at `whisper_bridge/` in the
  repo with its own `Dockerfile`.
- **Model:** `small` by default (~460 MB, good accuracy on short
  command-style utterances — provider names, numbers); `int8` quantization
  for CPU. Configurable via `WHISPER_MODEL` (`base` for lower memory).
- **Route:** `POST /transcribe` — multipart `file` → `{ "text", "duration_ms",
  "language" }`. Bearer-token auth (`WHISPER_BRIDGE_TOKEN`), shared with
  llm-proxy2. `GET /health` for the compose healthcheck.
- **Resources:** model loaded once at start; ~300–600 MB RAM resident;
  transcription of a short clip is well under a second on CPU. A
  `deploy.resources` cap keeps it bounded.
- **No persistence, no network egress** — it only receives audio from
  llm-proxy2 and returns text.

## 5. The transcribe endpoint

`POST /api/airi/transcribe` (in `app/api/airi.py`):
- Dependencies: `require_admin`, `_require_airi_enabled`, and a new
  `_require_airi_voice_enabled`.
- Body: `multipart/form-data` with an audio `file`. Size cap (~25 MB —
  generous for a few minutes of opus) rejected at the boundary.
- Forwards to `settings.airi_whisper_bridge_url` with the bearer token.
- Returns `{ "text": "..." }`. On a bridge failure: a clean JSON error, no
  stack — the panel falls back to "couldn't transcribe, please type".
- The audio buffer is not logged, not persisted; it lives only for the
  duration of the request.

## 6. The frontend — push-to-talk

In `AiriChatPanel`:
- A **mic button** beside the `Ask AIRI…` input. Renders only when
  `airi_enabled` *and* `airi_voice_enabled` (a new field on
  `GET /api/airi/status`).
- Tap → `navigator.mediaDevices.getUserMedia({audio:true})` →
  `MediaRecorder` records → tap again to stop → the blob is POSTed to
  `/api/airi/transcribe` → the returned text fills the input.
- States: **idle** (mic icon) → **recording** (pulsing, a stop affordance)
  → **transcribing** (spinner) → text in the input. The operator always
  reviews/edits before Send — voice never auto-sends in v4.2.0.
- Mic-permission denied, no `MediaRecorder`, or a transcribe error → a
  short inline message; the text path is unaffected.
- `getUserMedia` requires a secure context — satisfied by the production
  HTTPS origin and by `localhost`. Mobile Chrome and Safari both support
  `MediaRecorder`; the button is a full touch target.

## 7. Config & feature flags

- `airi_voice_enabled: bool = False` (`AIRI_VOICE_ENABLED`) — the v4.2
  feature flag, same discipline as `airi_enabled`. Off until the build is
  complete and QA'd.
- `airi_whisper_bridge_url: str` (`AIRI_WHISPER_BRIDGE_URL`) — the sidecar
  URL on the docker network (default `http://whisper-bridge:9000`).
- `airi_whisper_bridge_token: str` (`AIRI_WHISPER_BRIDGE_TOKEN`) — the
  shared bearer secret.
- Sidecar env: `WHISPER_MODEL`, `WHISPER_BRIDGE_TOKEN`.

## 8. The "Airy" wake word — deferred hands-free milestone

True always-listening means the dashboard mic is always on — a real
privacy and battery cost — so it is **not** the v4.2.0 default. It ships
later as an **opt-in hands-free toggle**:
- Wake-word detection runs **locally in the browser** (`openWakeWord` via
  onnxruntime-web/WASM) so no audio leaves the device until "Airy" fires.
- "Airy" is a custom word — it needs a small wake-word model trained via
  openWakeWord's synthetic-speech pipeline. That training + the toggle UI
  is the hands-free milestone's scope.
- When "Airy" is detected, the following utterance is recorded and sent
  through the same `/api/airi/transcribe` path.

## 9. Scope

**v4.2.0** — the whisper-bridge sidecar, `POST /api/airi/transcribe`,
push-to-talk mic button in the AIRI chat panel, feature-flagged. Input
only.

**Later (v4.2.x / v4.3)** — "Airy" hands-free wake word (§8); AIRI
text-to-speech ("Airy" speaks answers back).

**Non-goals (v4.2):** auto-send without operator review; transcription of
anything other than the operator's own chat input; storing audio.

## 10. Build milestones

1. **STT backend** — the `whisper-bridge` sidecar (Dockerfile, faster-whisper,
   `/transcribe`, `/health`, token auth); `POST /api/airi/transcribe` in
   llm-proxy2; the config flags; `/api/airi/status` exposes `voice_enabled`.
2. **Push-to-talk UI** — the mic button, `MediaRecorder` capture, the
   transcribe-and-fill flow in `AiriChatPanel`; recording/transcribing
   states; permission + error handling; mobile-responsive.

v4.2.0 = milestones 1 + 2. Each milestone is smoke-tested live (a real
microphone clip transcribed through the real sidecar) before it is called
done — the AIRI 4.0 discipline. The fleet stays on v4.1.1 throughout;
nothing deploys until v4.2.0 is built and QA'd.

## 11. Resolved decisions (2026-05-17)

1. STT engine = self-hosted OSS `faster-whisper` — the Web Speech API is
   ruled out by the locked own-the-dependency-chain rule.
2. Whisper runs as a **sidecar** container (grok-bridge pattern), not
   in-process — keeps its memory/CPU off the proxy.
3. v4.2.0 activation = **push-to-talk** (tap the mic). The "Airy" wake word
   is designed (§8) but lands in a later hands-free milestone.
4. v4.2.0 is **input only** — no text-to-speech.
5. Feature-flagged (`airi_voice_enabled`, default off); audio is transient
   and never persisted.
