# llm-proxy2 v4.3.0 — QA Report

**Date:** 2026-05-18
**Build under test:** v4.3.0 — the released `dblagbro/llm-proxy2:4.3.0` +
`dblagbro/whisper-bridge:4.3.0` images, live on all 3 fleet nodes.
**Pass type:** deep regression + release hardening + integration + operational
+ readability validation.
**Verdict:** ✅ **Release sound** — 2130/2130 unit tests + ~42 live checks
pass. No critical / high / medium defects. 5 low-severity / coverage /
operational findings logged (BUG-020 … BUG-024) — none release-blocking.

---

## 1. Scope

A full QA pass on **v4.3.0** (AIRI text-to-speech). Deep on the new TTS
surface; regression over the v4.2 voice surface and AIRI; a broad sweep of
the proxy core, auth, themes, and the 3-node fleet.

## 2. Method

- **Unit suite** — all 2130 `tests/unit/` tests.
- **Isolated throwaway stack** — the released `dblagbro/llm-proxy2:4.3.0` +
  `dblagbro/whisper-bridge:4.3.0` images, AIRI + voice + TTS flags on, wired
  together on a private docker network, running on an **isolated copy of the
  production database** (`CLUSTER_ENABLED=false` — it never touched the prod
  cluster). Real LLM calls, real Piper synthesis, real Chromium.
- **Live fleet** — read-only health/version checks against all 3 nodes.
- **Teardown** — all throwaway containers, network, DB copy and temp files
  removed afterward. **No production artifacts were created** (the one AIRI
  conversation produced by the integrated-TTS test lived only in the
  throwaway DB copy, which was discarded).

## 4. Safety properties re-verified

- TTS text + synthesized audio are **transient** — never persisted (the
  sidecar uses a temp file deleted on context exit).
- `/api/airi/speak` is admin- + `airi_enabled` + `airi_tts_enabled` gated;
  unauthenticated → 401.
- The sidecar `/speak` is bearer-token guarded; wrong/no token → 401.
- Synthesis runs entirely on our own infrastructure (self-hosted Piper) —
  the own-the-dependency-chain rule holds.
- TTS only reads back what AIRI already wrote — no new data exposure; a
  failed read-aloud is swallowed and never disrupts the chat.

## 5. Findings (see `bug-log.md`)

No critical / high / medium defects. Logged:
- **BUG-020** (low, observability) — pre-login `/api/auth/me` 401 logs a
  console error on every fresh load. Benign, pre-existing.
- **BUG-021** (low, coverage) — the message→speak wiring has no automated
  test, only the live smoke.
- **BUG-022** (low, coverage) — audible TTS playback can't be verified in
  headless Chromium; needs a real-browser manual check.
- **BUG-023** (low, operational) — c1conv at 9/10 healthy providers.
- **BUG-024** (enhancement, a11y) — voice buttons' `animate-pulse` has no
  `prefers-reduced-motion` guard.

## 6. Caveats / coverage bounds

- Audible TTS output and the autoplay-policy edge case were not verified —
  headless Chromium has no audio device (BUG-022).
- Proxy-core deep testing (`/v1/messages`, `/v1/chat/completions`, routing,
  cross-family translation) was **not** re-exercised live this pass — it is
  covered by the 2130-test unit suite and the integration suite; this pass
  bounded live testing to the v4.3/v4.2/AIRI surface plus a proxy-core sanity
  check.
- Mobile/responsive layout and deep keyboard-accessibility were not
  exercised this pass.

## 7. Conclusion

v4.3.0 passes a full QA pass. The new TTS surface — the Piper sidecar, the
`/api/airi/speak` endpoint, the speaker toggle, and the integrated
answer→speech flow — works end-to-end; the v4.2 voice surface and AIRI are
unregressed; the proxy core is green on 2130 unit tests; the fleet is
uniformly on v4.3.0. **The release is sound.** The 5 findings are
hardening / coverage / operational items — none block the release. See
`remediation-plan.md` for the (post-review) fix plan and `backup-plan.md`
for the snapshot/rollback procedure.
