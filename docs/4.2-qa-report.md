# llm-proxy2 v4.2.0 — Post-deploy QA Report

**Date:** 2026-05-17
**Build under test:** v4.2.0 (the released `dblagbro/llm-proxy2:4.2.0` +
`dblagbro/whisper-bridge:4.2.0` images)
**Verdict:** ✅ **50 / 50 checks passed**

---

## 1. Scope

A full post-deploy QA of v4.2.0 — a **regression pass** over the whole
product (the v4.0 → v4.1.1 surface) plus the **new voice input** (group K).

## 2. Method

A throwaway smoke from the **released images** — `dblagbro/llm-proxy2:4.2.0`
with `AIRI_VOICE_ENABLED=true`, wired to a `dblagbro/whisper-bridge:4.2.0`
sidecar — on an isolated copy of the production database. Every chat turn
ran a real LLM; voice ran a real speech clip through the real Whisper
sidecar; UI checks drove real Chromium. Torn down afterward; the production
fleet was untouched. Additionally: 2117 unit tests passing.

## 3. Results

### Group A — chat + grounding (6/6)
Feature flag · explain-routing · grounded provider list (10/10 real names) ·
supervisor-state faithfulness (3 runs agree) · activity-log grounding ·
capability grounding (the opus-4.7 question).

### Group B — rules & rule-sets (4/4)
Default seeded · save-as · activate · restore-default.

### Group C — propose / apply / revert + safety (5/5)
Pending-by-default · apply · revert · over-large change capped ·
**adversarial** bulk-disable contained (0 applied, 10→10 enabled).

### Group D — scheduled rules + kill switch (3/3 + evaluator live-fire)
AIRI proposes a scheduled rule · approved rule lands in the active set ·
kill switch ON/OFF · **evaluator live-fire** — a monitor rule fired with
**zero LLM calls**.

### Group E — history + cross-user search (3/3)
Conversation event · listed for its owner · cross-user search.

### Group F — notification preferences (3/3)
GET default · PUT saves · bad email rejected (400).

### Group G — capability-fit gate (3/3)
Vision request skips a non-vision provider · oversize request skips a
small-context provider · tools+reasoning is **not** skipped (co-emulation).

### Group H — tool + CoT co-emulation (1/1)
A provider native in neither served a tools + reasoning request →
`X-Emulation-Level: enhanced` + a real `tool_use`.

### Group I — robustness (3/3)
Empty `messages[]` → 400 · unauthenticated → 401 · unknown conversation → 404.

### Group J — UI (10/10, real Chromium)
All five AIRI panels render (chat, rule-sets, scheduled rules, change log,
notification prefs) · chat streams a reply · history/search drawer opens ·
sticky chat survives navigation · **zero console errors**.

### Group K — voice input (8/8) — the v4.2.0 surface
- **STT backend** — `/api/airi/status` reports `voice_enabled`;
  `POST /api/airi/transcribe` ran a real speech clip end-to-end through the
  whisper-bridge sidecar and returned the correct transcript
  ("Show me provider health."); empty audio → 400.
- **Push-to-talk UI** — the mic button renders when voice is enabled; tapping
  it starts recording; on stop the clip is transcribed and the transcript
  fills the chat input; voice **does not auto-send** (the operator reviews);
  the mic returns to idle.

## 4. Safety properties re-verified

- Two-stage commit; the per-turn blast-radius cap (adversarial bulk-disable
  applied nothing); rule-set caps; the no-LLM evaluator; the never-hard-fail
  capability gate; co-emulation composing tools + reasoning.
- **Voice** — audio is forwarded to the self-hosted sidecar and never
  persisted; the transcript fills the input for operator review before Send,
  so the PII/guard path still applies; transcription stays on our
  infrastructure.

## 5. Caveats

- Chromium's headless fake-audio device is unreliable, so the browser's mic
  *capture* was stubbed in group K-ui — everything downstream (the component,
  `/api/airi/transcribe`, the sidecar) is real. The STT backend itself
  (group K) was exercised with a genuine speech clip.
- Co-emulation uses the lightweight reasoning-prefixed tool prompt, not the
  full multi-pass CoT pipeline — a deliberate bound.

## 6. Conclusion

v4.2.0 passes a full post-deploy QA — **50/50** — on the released images.
The whole 4.0 → 4.1.1 surface still works, and voice input (the STT sidecar,
the transcribe endpoint, the push-to-talk mic button) works end-to-end. The
release is sound; voice is ready to be turned on (`airi_voice_enabled`).
